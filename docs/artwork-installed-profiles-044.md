## Native guard experiment

An exclusive noninteractive Proof package can now select a no-dispatch guard
recipe. On the first launch it creates a measured own pending record and drops
the ticket without clearing it. On a second process in the same installation,
the existing record must block a newly constructed provider as Unavailable.
The recipe does not start a worker, fetch artwork, invoke HBC or provision a
Root helper. Each phase holds for eight seconds for independent process/file
binding and captures Home before swap, without settings, favourite or app actions.

This is a controlled restart test, not an intentionally lost Root completion.
The coordinator must bind both distinct ordinary processes and the same persisted
first-process record, prove no owned helper was staged and inspect complete
helper/namespace absence before exact pending-file removal and supported Proof
uninstall. It does not qualify recovery from an unknown real Root/helper/child
outcome. The recipe itself has no clear-old-record or recovery API.

The separate positive package exercises the shared installed resource path and
must show its pending record during the first helper, then its absence before
uninstall after every known operation closes. Preserve all normal bundle/state
bytes and checked metadata; an expired timer, missing receipt or successful scene
alone cannot clear a startup barrier.
