# Installed artwork renderer, 0.43

This component connects the [0.42 installed provider](artwork-installed-provider-042.md)
to the ordinary worker, cache and native renderer in an isolated Proof package.
It does not update either retained Preview. The live catalogue remains enabled;
action dispatch and normal scripted navigation are disabled in this mode.

An isolated G2 run completed the combined installed-provider → worker/cache →
native Home/Apps path. Six transfers finished, each with one joined helper;
three distinct live targets were fully visible on both captured pages. Those
are the same three displayed targets across the two pages, not six different
visible apps. Five transfers used encrypted-app sources and one used a developer
source. This is not all-app or all-installation-class qualification.

Root reviewed both saved native frames: icons retain their source shape on
black without an added backing plate, focus outlines are visible, and Apps
retains a missing-artwork initials fallback. The Luma header's raw pixels are
identical across both frames. The isolated recipe does not poll the normal
main-loop clock, so its unavailable clock is outside normal-clock qualification.
Raw captures and actual household inventories remain private.

The test must show at least three distinct, fully visible live textures on each
of Home and Apps. Saved source identities, encoded digests, decoded pixel hashes,
actual card geometry and texture handles distinguish these from packaged icons.
Raw framebuffers are captured before swap and retained before external visual
classification. These native reports alone are not an independent pixel oracle.
The existing icon presentation preserves source shape, aspect and transparency
on black; only missing artwork uses the graphite initials/name fallback.

Each observed fetch saves bounded, immutable own-process metadata before its
Identify request and after joining the HBC completion thread. The first fetch
alone pauses for eight seconds to permit an independent live process binding.
Later peers remain kernel/Root/HBC observations unless separately sampled by the
operator. At most sixteen fetches may dispatch; the next attempt writes one cap
receipt and refuses dispatch. Encoded image bytes are not logged. The ordinary
provider has neither the diagnostic hold nor these receipt writes.

On success or failure the recipe pauses new dispatch, drains outstanding work
and joins the worker, then deletes its live textures. The operational deadline
is 120 seconds; cooperative SDK/kernel joins have no guaranteed hard bound.
Root-helper/child absence, protected-helper removal, supported Proof uninstall,
normal Preview preservation and lease removal still require the external device
carrier. Unknown helper or child completion must stop admission rather than
trigger another Root launch or an inferred cleanup success.

Host validation passes 398 library tests, five dashboard tests, Clippy with
warnings denied and 41 Python build/provenance/framework/package tests. A receipt
writer portability failure was corrected before the passing Rust run: directory
link counts may change as receipts are created, so directory identity uses
device, inode, owner, group and mode. Receipt files still require exactly one
link before and after writing.

Both ARM binaries build from functional source
`e7f60903349ed5ad5dbdfcb19cf6d99c3865da39`, with matching snapshots of 95 selected
inputs and the pinned framework. The [compiled candidate](artwork-installed-renderer-043-candidate.json)

warning remains. Compilation does not establish the combined device path.

The locally built ordinary Proof IPK has 30 files: 23 private snapshot/icon
assets, four font/branding resources, app metadata, the executable and the one
four-field installed-artwork marker. Archive readback matches the frozen bytes
and modes. The Root executable and its protected installation policy are separate
artifacts, absent from this IPK. No services or install hooks are bundled. This
is separate package admission evidence; the subsequent run used this exact IPK.

All six indexed results, including background/drain work, reconciled with runtime
submission/completion counts. The first helper was independently measured live;
the other five bind ordinary kernel peer/message records, Root self measurement
and joined HBC completion. All 96 known Core child PID/process-group pairs were
