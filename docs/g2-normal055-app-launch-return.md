# G2 normal 0.55 app launch and fresh return

The retained 0.55 preview launched a separate owned native test application from
its real app drawer. Luma ended on window departure, joined its icon worker and
released its uploaded textures. After the test application ended and was removed,
a new normal Luma process completed Home → Apps → Home → Back exit. LG Home
remains the system home; returning to Luma required an explicit SDK launch.

The original operator remains **exit 1**. It checked the catalogue immediately
after the single successful removal acknowledgement and still found the Target
there, although its launch point had already disappeared. It stopped without
retrying removal or launching Luma again. The acknowledgement was not treated as
completed removal.

A separate continuation under the same original lease and absolute time limits
observed completed removal, cleaned only the positively bound test runtime and
staging files, then performed the planned fresh Luma return. It ended with exit 0,
verified lease release and private host-agent termination. This later success
does not change the original operator's failed full-workflow result. The
independent saved-evidence audit passed, and a separate coordinator replay
produced the same report bytes. The [sanitized milestone](g2-normal055-app-launch-return-milestone.json)
records these distinct outcomes.

The first executed saved reader remains exit 1: it compared a nested
path/directory record with the inner identity fields. The corrected reader
checks both the exact path and full original directory identity. No TV action
or raw-evidence change was needed for that correction.

## Observed scope

- The coordinator reviewed the actual drawer card before one guarded OK launched
  the owned Target. A fresh identical full compositor image, process identity and
  sole-card checks preceded OK. These are sampled checks, not atomic input delivery.
- Luma's terminal record contains one admitted, verified application action and
  a window-hidden exit. The separate Target had a live native record, matching
  executable/process identity and foreground/card observations. Its initial record
  is not an exit receipt, and no OS exit status was measured.
- Original Luma shutdown joined its worker, balanced 13 packaged-icon uploads and
  deletions, left zero textures and recorded zero icon backend errors. The fresh
  return did the same for seven textures. These counts exclude other renderer
  resources and do not establish all-app artwork coverage.
- The final full 0.55 bundle, private preference bytes/ownership and sampled Core
  readings matched their original baselines. No preference write was queued.
  Normal runtime logs and session receipts remain intentionally; preexisting
  runtime bytes were not rehashed.
- Removal closure included catalogue and launch-point absence, absent package,
  jail and state paths, absent Target UID/executable and no remaining mount
  references. Only the original observed runtime directory and its known leaves
  were deleted. There was one SDK removal request in the original run and none
  in the continuation.

No retained Preview install/uninstall, settings or favourite mutation, Root
artwork helper, household app launch, Home interception or boot change was
requested. C2 was not contacted. Physical input, automatic return, arbitrary-app
compatibility, performance and general reliability remain unqualified. The
retained [G2 delivery](g2-retained-preview055.md) stays at 0.55; the
[0.56 TV-information source](device-information-056.md) has not been deployed.
