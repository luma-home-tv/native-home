# Actual Preview artwork admission candidate, 0.45

This candidate adds an explicit diagnostic under the retained Preview application
identity. The [0.44 isolated results](artwork-installed-profiles-044.md) establish
the separate Proof resource path and restart guard, not Preview permissions.
Normal interactive artwork activation remains off.

The package contains the same four-field public marker and no Root helper,
configuration, service, permission or boot payload. Its packager admits only the
actual Preview identity, matching ARM UI/helper build receipts and protected
six-field Preview installation pins. All other trial/action parameters are
excluded. The separate fixed helper selects Preview in source.

The diagnostic requires existing initialized private preferences. Its state
opener never creates a directory; it starts no persistence, action, pointer or
numeric-control worker and queues no preference writes. A joined inert Preview
`checkRoot` observation precedes an eight-second Home hold. Any input, changed
preferences or unqualified capability prevents resource-worker creation. That
branch records zero resource jobs and Root exec attempts without claiming a
permission diagnosis. Every created-resource-worker branch instead needs full
resource, pending-record, Root/child, Finish/EOF and joined HBC reconciliation.

The successful branch reuses the two-page observation with three fully visible
live targets per page, preserving actual saved favourites. It does not reseed
favourites to satisfy the test. Complete Root helper/child closure and pending
absence must precede supported restoration of the backed-up 0.37 package.
Unknown installer, lease or remote completion retains the cleanup barrier.
The retained Preview is never uninstalled or reset by this experiment.

Host checks pass 442 library tests, five dashboard tests, warnings-denied Clippy
and 57 Python package/provenance/framework tests. An initial Python run retained
three failures from old package-version expectations; updating those assertions
to the new package version resolved them. Review also replaced a create-capable
state opener with an existing-only opener and a missing-directory/symlink
regression. ARM compilation and actual Preview-ID execution remain pending.

This experiment does not qualify ordinary production activation, post-keyboard
or foreground-departure recovery, C2 Root artwork, all-app compatibility,
performance, physical input or changes to LG Home. LG retains control of core
services, boot behaviour and OLED protection. The attributed
[PlxNative framework](../README.md#plxnative-framework-dependency) continues to
provide the native graphics/UI foundation without Plex client features.
