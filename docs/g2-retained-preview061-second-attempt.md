## Diagnosis boundary

This reader uses native LS2 calls, not `luna-send` subprocesses. Each of its three
fixed context calls has a remaining-budget cap of 500 ms. Timeout and setup
failures currently collapse to the same unavailable value. The receipt therefore
cannot distinguish those causes or exclude a returned JSON value of that shape.
The foreground did not demonstrably leave the app; `context_changed` is the
source's refusal classification, not proof of an actual foreground departure.

The capability operation reported 1,148 ms elapsed and no expired overall
eight-second deadline. That does not rule out a 500 ms per-call timeout. Its
`context_first` and `context_before` are copies of one initial snapshot, not two
independent successful reads. The host's earlier held-stdin repair does not apply
to this native LS2 path.

Follow-up work will retain bounded typed results and per-call timing for the
existing requests. It must preserve the context Values, request order, budgets,
refusal rules and resource-dispatch barriers. No timeout increase or retry is
justified by this receipt alone.
