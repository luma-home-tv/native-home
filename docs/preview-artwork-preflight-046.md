# Preview preflight rendering and resource result, 0.46

The G2 completed a temporary diagnostic under the actual Preview application identity: its context qualified, the initial inert `checkRoot` call returned true, and the installed resource path delivered six accepted transfers through six helpers. Home and Applications each showed three fully visible live targets—the same three distinct targets across both pages. The coordinator then restored the exact normal 0.37 installation. This is scoped actual-ID resource evidence, not normal product activation.

The [milestone record](preview-artwork-preflight-046-milestone.json) binds the completed device run and saved audit. The separate [compiled candidate record](preview-artwork-preflight-046-candidate.json) preserves its earlier build-stage snapshot; its pre-device qualification flags were not rewritten after the result.

## What changed and what was observed

The [0.45 experiment](preview-artwork-admission-045.md) reached a context deadline before attempting `checkRoot` or creating a resource worker, then restored normal 0.37 exactly. Its saved final contexts contained deadline placeholders. Source inspection found a collector join before the first diagnostic draw/swap, but that result did not establish a permission denial or prove the cause of the timeout.

Version 0.46 presents Home before starting the collector and keeps rendering and events running during the existing eight-second hold until the worker finishes. Joining happens afterwards. An interruption suppresses subsequent drawing and resource-worker creation. The five-second foreground gate, eight-second operation budget, fixed service calls, protected profiles, marker, pending guard and resource policy remain unchanged. SDK setup, destruction and joins retain their existing soft lifetime boundary.

The first context observation was retained and showed a fresh Preview CARD. It is diagnostic evidence only: current before/after contexts, identity and deadlines still decide admission. The initial inert check succeeded. Each of the six fetches also performed its own fresh capability check before its fixed Root startup request; there was not just one HBC request for the entire run.

This successful follow-up supports the rendering-order explanation for 0.45, but it is not a controlled causal or reliability result. It does not establish how often an earlier timeout would recur.

## Resource closure and restoration

Every recorded resource job was reconciled, including its kernel credentials, full source key, file/digest readback, completion, Finish/EOF and joined HBC result. Six helpers and all 96 known Core-reader child PID/process-group pairs were closed. Only the first helper had independent live external process records; later helpers were bound through kernel credentials, Root self evidence and joined HBC completion.

The first pending record was captured against the measured ordinary Preview process before the first external Root-process measurement. Its absence was independently observed before supported same-ID restoration. The exact temporary Root helper/configuration files and directory were removed after known closure. The original 0.37 bundle, preferences, complete state bytes and checked ownership/modes matched after restoration, with all 20 checked state domains and five Core hashes unchanged. No preference writes, uninstall or state reset were requested. Only 21 new diagnostic runtime files were removed; preexisting runtime folders were preserved. Uploads, the lease and private host agent were cleaned up, LG Home was current, and closeout had no errors or unknown barrier. The restored old code was not relaunched by this test.

The saved audit and a byte-identical replay exited 0, with **28,351 assertions**. The result hash is `d2dc01f27feaf33f207b2ca0f19e2dc4e77546704a2e8f3ad11e71a599206bfc`. It checked the frozen functional commit and 99 selected inputs rather than a newer working tree.

Root reviewed both saved native frames: icons, the black canvas without an added icon plate, labels, branding and focus outlines were visible. The branding header's raw RGB region matched across the two frames, with 15,857 nonzero channel bytes. These observations are not an independent reconstruction of image pixels from encoded source bytes, text OCR, a physical OLED-panel observation or a performance result. The unavailable clock remains a limitation of this isolated recipe's polling path, not a normal clock regression.
