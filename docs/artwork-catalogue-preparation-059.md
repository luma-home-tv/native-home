# Explicit catalogue preparation: 0.59 source integration

The diagnostic preparation path now executes a selected batch from the whole
fresh preferred-icon catalogue. It no longer uses the number of visible Home or
Apps cards as its stopping condition. Normal interaction remains separate: a
cache miss does not launch Root work.

The source, host checks, matching ARM builds and local package/ABI inspection now
pass. This is not a retained TV update: the last verified G2 preview remains
0.57. A later [temporary native batch](artwork-catalogue-preparation-059-native.md)
prepared 15 of 16 images, skipped the consumer and restored exact 0.57 with
independently audited known cleanup. Its operator exit 1 remains preserved;
complete preparation and normal delivery remain open.

## Exclusive selection and execution

The packager's explicit `NATIVE_HOME_CACHE_PREPARATION=1` mode requires its private
selection pins, the existing actual-Preview diagnostic admission, independently
matched UI/helper builds and producer association, protected startup pins, and
noninteractive ARM Preview. Other modes and unexpected parameters are refused.
Normal producer sidecars remain inert as preparation selectors.

The fixed `artwork-cache-preparation.json` asset contains exactly schema 1, the
matching UI digest and a mandatory cursor field. The cursor is either null or
the strict [planning cursor](artwork-catalogue-planning-059.md). Duplicate, unknown,
coerced or oversized fields are refused. The ordinary runtime reader checks a
bounded, stable, single-link Root-owned regular package file; it does not hash
the executable or read the cache on the UI thread. The existing provider checks
actual self identity and loads the fixed producer association on its worker.
Selection metadata grants no Root path, command or completion authority.

After the existing inert capability preflight, the recipe keeps Shell's Root
runtime absent and owns one existing image worker directly. It does not create
an action, persistence, pointer-setting or description-setting worker, process
remote input into UI actions, or queue preferences. It enumerates at most 16
sealed preferred sources, rechecking the independent live source map immediately
before each submission. It uses the same `live_origin` clock as the observations.

Each attempted source gets one tiny private scheduler with exactly that sealed
source. Its purpose is existing `Work` ownership, not visible-card priority,
refresh or retries. Returned CPU pixels are dropped after accounting; Root
artwork is never uploaded to GL by this recipe. Packaged baseline rendering may
continue while the diagnostic remains active.

The original logical batch budget is 180 seconds. New work stops at 120 seconds,
reserving a 30-second job budget plus 30 seconds to drain. Progress never resets
that deadline. Input/departure latches stop new work and presentation; caller
invariant or graphics failures stop dispatch without falsely reporting remote
input. Any already-owned job is polled to actual completion before the real
worker join. Cancellation, Drop or an empty queue cannot establish Root closure.
Blocked SDK, codec, filesystem or teardown calls still have no hard total-time
guarantee.

## Actual progress versus authority

The fixed new provider wrapper emits at most one bounded in-memory event per
fetch. It records the actual observer index, fetch sequence, full source key,
current-Ticket resolution, provider settlement, and optional ordinary publication
outcome. Old factories, wire protocol, fixed HBC command, context checks,
16-attempt observer cap, first-fetch hold, required result writes and pending
guard remain unchanged.

Before each submission the event channel must be empty. Each completion consumes
one event and requires no extra event, exact retained `Work` and full source key,
matching sequence/index, and known closure in both the event and the worker.
Missing, stale, duplicate or inconsistent events permanently stop the batch;
they never realign counters or clear an unknown Ticket. A worker interruption
before `fetch` therefore cannot reuse a previous publication record.

Publication precedes worker validation and decoding. A local prepared-image
record requires successful publication and receipt writing, actual decoded
completion, matching encoded digest/length/full file identity, and a still-current
catalogue. Publication failure, invalid encoding, failed decode and cancellation
remain distinct partial outcomes. Their ordinary-cache status cannot rewrite
Root settlement. An empty enumeration cannot claim a prepared batch.

The recipe polls live data again after join and compares the full current keyset.
It does not claim a newly returned service reply after join merely because it
performed a poll. Reports keep external helper/child/pending closure, final cache
body coverage, all-catalogue preparation, native pixels and performance unverified.
An enumeration cursor never proves prior execution or continuity across processes.

Clippy pass. The [milestone record](artwork-catalogue-preparation-059-milestone.json)
binds source and check logs. Independent source reviews cover the runner,
selection reader, Main/recipe and closed package mode. A subsequent header-only
clarification distinguishes prepared artwork from existing packaged fallback
uploads; it changes no runtime logic. Controlled worker tests use synthetic
publication observations; they exercise the actual worker and bounded decoder,
not a Root helper or native cache publication. File-reader fixtures use the
host's actual owner through a private test seam and do not establish TV ownership.

Both actual ARM build receipts bind the same 132 committed source inputs at
`dd2671da4e9288b1bef668ad9257a5bae1870d59`, with the attributed framework unchanged.
The normal and explicit-preparation packages contain the same UI and producer
association; their role-specific markers differ. An independently authored,
source-reviewed local auditor checks every source Git blob, archive framing and
ordinary payload using its own parser plus SDK `ar`, and inspects the ELF loader,
direct libraries and required GLIBC versions with SDK `readelf`. Twelve synthetic
auditor guard cases pass. The UI requirements fit the actual retained 0.57 UI;
the helper requirements match the specifically bound native 0.46 helper. These
comparisons do not qualify transitive loading or new executable permissions.

The first audit correctly refused a newly generated package receipt with mode
0644. Both new receipts had that mode; the coordinator changed only those own files to 0600,
preserving their bytes and both package hashes. The failed audit record remains
separate; a fresh audit then passes. Coordinator readback rehashes all 175 bound
inputs and 501 saved inspector outputs. The exact 0.57 rollback archive matches
its saved complete bundle. No TV, target ELF or helper was executed by this
local inspection. Packages and household resources remain private.

The next step is the bounded icon fix identified by that partial native batch,
then matching artifacts and a fresh separately reviewed G2 trial against its
actual retained bundle and preferences. Native acceptance must independently establish every attempted
helper's disposition, current-Ticket/child/socket closure, ordinary cache

Unknown ownership or lifecycle retains its barrier.

Multiple batches, final per-key body readback, capacity/partial-result handling
and a product-facing preparation flow remain unfinished. The planner's 512-entry

This integration introduces no LG Home interception, boot, firmware, system,
jail, media, network or OLED changes. Rendering and decoding continue to build on
the attributed PlxNative engineering; Plex features remain outside Luma Home.
