# C2 native startup collection

A temporary native observer ran on the C2 and produced independently bound startup reports. A separate cleanup operation then removed its measured files and staging package and released the same coordination lease. The retained 0.20 dashboard and its preferences remained unchanged.

This qualifies collection mechanics and the observed native launch argument shape for a new, isolated Launch Target identity. It does not qualify the retained Preview identity, preference migration, or a normal upgrade.

## What was measured

The isolated observer package was version 0.1.1 on the C2 running firmware 23.25.55 / webOS24 SDK 9.2.2. Its frozen private source snapshot contained 102 selected inputs and 10 pinned framework patch files. The ordinary process was independently bound using seven kernel reads, including its executable bytes, process start, credentials and jail. A native self-report was supporting evidence, not its own authority.

The observer created no window and requested no SDK, HBC, Root helper or preference operation, and changed no existing permissions. It saved an early report and a completion report after its reported eight-second observation window. Five saved completion captures were byte-identical. Nine live snapshots established that the observer's specific output parent, leaf and early report mapped to the measured host paths while that same process was alive. This is a narrow mapping result, not a general mapping of the TV's temporary filesystem or a guarantee about namespace survival.

The process received its executable path and a 176-byte JSON object. The reports retained bounded lengths, hashes and structural summaries; raw argument values were not saved. This gives a concrete ABI observation for this identity and package. It does not establish why the earlier same-ID Preview migration attempt produced no fresh report at the checked host location; that attempt remains unresolved.

## Failures remain failures

The three host operator sessions have distinct outcomes:

| Host tool session | Actual exit | Result |
| --- | --- | --- |
| 7850 | 1 | Refused before Home, upload, installation or native launch because the carrier expected the wrong launchpoint identity field. The actual SDK arrays use `id`. |
| 1440 | 1 | Captured and bound the observer, then removed its package through the supported SDK. Cleanup refused an extra completion file because the carrier confused the filename `completion.json` with the native JSON stage `complete`. |
| 51768 | 0 | A separately reviewed cleanup-only operation recognised the unchanged, source-correct saved completion and closed the exact measured output and upload scope. |

The cleanup did not repeat installation, native launch, package removal or navigation. It required fresh process and assigned-credential absence, the recorded successful package removal plus registration and bundle absence, exact mapped directory identities, both report bytes and metadata, the staging identity and package hash, and the unchanged original lease owner. No Home action or wake was used in these actual observer and cleanup operations. Neither failed session was regraded as successful.

## Preservation and acceptance limits

The independent saved audit bound the retained bundle's 42 entries / 40 files and the original 216-byte preferences, including their recorded 0777 modes, across the measured snapshots. Five Core-file digests and 19 typed read domains matched the 20-domain baseline. The exact two report files, their two directories, the staged package and its directory were removed through six bounded deletion operations. The same original lease was released and the private host agent was closed. The SDK removal has a literal successful reply and absence readback; no removal subscription terminal is claimed.

The saved audit passed 9,516 named checks with 5,271 file bindings. Root separately replayed the unchanged audit function with equivalent output serialization, obtained exit 0 and a byte-identical report. These counts describe evidence bookkeeping, not product coverage or performance.

No native process exit code was measured. There is no qualification of Preview credentials or Root artwork authority, preference migration, general temporary-path access, rendering, physical-panel behaviour, performance or the subsequent 0.48 path. The retained C2 dashboard is still 0.20. Public documentation contains hashes and summaries; raw reports, process identifiers, argument values, app inventories and device addresses stay private.

See [the 0.47 migration plan](preferences-migration-047.md) for the separate own-preferences operation. This observation does not turn that proposed or failed operation into a native pass.
